# Worklog

For worklog requests, start token tracking with `python3 timesheet-logger/scripts/track_token_usage.py begin --prompt "<user_prompt>"`. Choose the requested period: `morning` for morning/sáng (09:00–12:00), `afternoon` for afternoon/chiều (13:00–18:00), and `full` when the user asks for the whole day or does not specify. Run `python3 timesheet-logger/scripts/run_worklog.py --date YYYY-MM-DD --work-period <period> --draft-only` (date defaults to today). Only include GitHub PRs with commit, review, or comment timestamps inside the requested period; never move afternoon activity into a morning draft. Cap each unique PR/task at 4 hours total per date; leave any excess time unassigned if no other evidenced task can take it. The collector uses Python HTTPS requests to GitHub and Google APIs, so allow outbound network access for this draft command when the environment prompts. If `gh auth status` is already successful, do not ask the user to log in again solely because the Python collector cannot connect; report the network failure and retry after network access is enabled. Finalize token tracking with `python3 timesheet-logger/scripts/track_token_usage.py finalize --run-id <run_id>` immediately upon drafting. Visualize the generated entries as a calendar; if unavailable, show the JSON in chat. Wait for explicit approval, then run `python3 timesheet-logger/scripts/push_worklog.py submit --input timesheet-entries.json --confirm`. Never inspect user source code or upload before approval.
